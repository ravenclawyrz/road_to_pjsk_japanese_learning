## 1 项目概述

### 1.1 原始构想
利用游戏《世界计划》（Project Sekai，日服）的剧情文本，制作辅助日语学习的软件：用户输入某个日语词汇、语法等表达，软件在剧情中查询使用到该表达的对话，作为学习该表达的例句。

### 1.2 目标用户
喜欢《世界计划》游戏的日语学习者。软件界面为中文。

### 1.3 参与者
| 参与者 | 说明 |
|---|---|
| 学习者 | 主要参与者：使用软件查询、学习例句 |
| 数据维护者 | 次要参与者：剧情数据的导入与更新（可与学习者为同一人） |

### 1.4 范围与边界
- 纳入（第一阶段）：Windows 本地桌面应用；剧情例句的查询、结果展示、筛选、排序、复制、收藏、假名注音、数据更新。
- 本次不纳入（后续扩展，优先级从高到低）：Anki 导出、中文反查；以及账号与云端同步、移动端。

## 2 功能需求

| 编号 | 名称 | 优先级 | 描述 |
|---|---|---|---|
| FR-1 | 文本模糊查询 | 核心 | 用户输入一段日文文本（单词、短语或短句），软件在剧情库中执行模糊查询。模糊查询 = 子串匹配 + 活用形扩展（FR-2）+ 读音归一化（FR-3），按用户设置的容错级别（FR-12）执行。输入约束：非空、不全为分隔符、长度 ≤ 100 字符。 |
| FR-2 | 活用形扩展匹配 | 核心 | 动词、形容词、形容动词等有形态变化的词：用户输入基本形或其他任意形式，其全部活用形均纳入检索范围。包括：ます形 / て形 / た形 / ない形 / ば形 / 命令形 / 意向形 / 可能形 / 受身形 / 使役形 / 使役受身形 / 敬语，及复合表达（如「聞かせていただき」）。同时纳入口语缩约形（聞いてる、聞いとく、聞かなくちゃ、聞いたん 等）。边界规则：名词化派生（如 高い→高さ）纳入检索范围；相近的不同词条（聞こえる 等）默认不互通，仅在强容错级别下与 聞く 互通（见 FR-12）。 |
| FR-3 | 读音归一化匹配 | 核心 | 支持以假名读音查询汉字写法的台词（输入「きく」可命中「聞く」）；查询与语料两侧统一做平假名/片假名互转、全角/半角统一、长音符（ー）容忍。读音归一化命中在相关度中低于书写形式命中（见 FR-7）。 |
| FR-4 | 分隔（通配）查询 | 核心 | 支持分隔查询语法条目：用户输入含分隔符的模式（如「……を……にして」），分隔符符号可在设置中指定（……、＊、※ 等，见 FR-12）。每处分隔符在单句台词内匹配任意长度（含 0 字）的内容；模式中的固定部分同样适用 FR-2、FR-3。 |
| FR-5 | 结果展示 | 核心 | 每条结果显示：台词原文（命中部分高亮，注音按 FR-10）、说话角色、出处（剧情类型 + 剧情/活动名称 + 话数/章节 + 台词序号）、国服译文（有对应译文时显示；国服未实装或译文数据不可得时留空）。支持展开查看该台词前后几句对话。结果分页展示（每页 50 条），总量上限 1000 条，超出时提示细化查询。 |
| FR-6 | 结果筛选 | 核心 | 按剧情类型筛选：主线剧情 / 活动剧情 / 卡面剧情（前篇·后篇）/ 区域对话 / 生日·纪念剧情。按团体筛选：Leo/need、MORE MORE JUMP!、Vivid BAD SQUAD、Wonderlands×Showtime、25時、ナイトコードで。、Virtual Singer。按角色筛选。各维度可组合。 |
| FR-7 | 结果排序 | 核心 | 排序方式：相关度（默认）、剧情实装时间（活动/章节发布顺序），各支持升/降序。相关度打分规则：① 命中形式——书写形式完全命中 > 活用变形/派生命中 > 读音归一化命中 > 通配分隔命中；② 查询表达式（固定部分）覆盖率；③ 同句命中次数；④ 同分时按实装时间排序。 |
| FR-8 | 复制与收藏 | 增强 | 一键复制选中例句（原文 + 角色 + 出处，可设置是否附译文/注音）；收藏例句，支持查看与移除收藏。 |
| FR-9 | Anki 导出 | 后续扩展 | 将选中例句或收藏列表导出为 Anki 可导入的卡片文件（如 .csv/.tsv），字段：正面 = 台词原文（可含注音）、背面 = 译文与出处。第一阶段暂不开发，列为后续扩展，优先级高于中文反查。 |
| FR-10 | 假名注音显示 | 增强 | 台词上方标注假名读音。注音优先使用数据源自带注音数据；数据源不含注音时，可用形态素解析生成读音（实现阶段按数据源情况二选一）。 |
| FR-11 | 剧情数据更新 | 核心 | 三种途径：① 随软件版本内置发布时最新的剧情数据；② 软件内「一键更新」——用户手动触发，联网从指定 GitHub 开源仓库拉取最新数据，校验格式与完整性后重建索引；③ 用户手动将符合格式的数据文件放入软件数据目录，软件检测后提示重建索引。更新失败时保留旧数据与索引并提示失败原因。 |
| FR-12 | 个性化设置 | 核心 | 匹配容错级别：弱（默认，仅子串 + 变形 + 通配）/ 中（额外容忍促音、长音符、拗音等轻微书写差异）/ 强（在中基础上，额外启用相近词条互通（聞こえる↔聞く 等）与编辑距离近似匹配，容忍少量假名拼写差异；注意可能引入不相关结果）。另含：默认排序规则、注音显示开关、分隔符默认符号、复制内容选项。 |

## 3 非功能需求

| 编号 | 名称 | 描述 |
|---|---|---|
| NFR-1 | 平台与部署 | Windows 10/11 64 位；免安装、解压即用（或标准安装包）；支持安装/解压路径含中文与空格。 |
| NFR-2 | 中/日文显示与输入（重要） | 界面及数据全程 Unicode（UTF-8）编码，正确显示中文与日文；所有输入框支持 Windows 中文输入法与日文输入法（微软拼音、微软日语 IME 等）正常输入与候选显示。 |
| NFR-3 | 性能（建议目标） | 数据规模数十万～百万台词行、本地索引；单次查询响应 ≤ 1s；冷启动 ≤ 10s；内存占用 ≤ 1GB。 |
| NFR-4 | 异常与容错 | 空输入、纯分隔符、超长输入给出明确提示；无结果时显示空态与查询建议（改用基本形、放宽分隔符、调整容错级别等）；数据文件缺失/损坏时启动提示并引导更新；首次启动加载数据时显示进度。 |
| NFR-5 | 合规 | 剧情文本版权归 SEGA / Colorful Palette 等权利方所有，本软件仅限个人学习用途，不商用、不分发剧情全文；所依赖的开源数据仓库须遵守其许可证，并在软件中注明数据来源。 |
| NFR-6 | 可维护性 | 数据更新与索引重建不依赖代码变更；查询、索引、数据层解耦，便于后续接入中文反查等扩展。 |

## 4 数据需求
- **数据源**：GitHub/Gitee 上的开源《世界计划》（日服）剧情数据库（实现阶段选型，候选如 SekaiViewer 系列仓库），需包含字段：剧情类型、剧情/活动名称、话数/章节、台词序号、说话角色、台词原文；可选字段：注音、译文。
- **预处理**：对全部台词做形态素解析与读音标注，构建本地索引（支撑 FR-2、FR-3 的匹配）。
- **译文对照**：以国服剧情文本逐行对照日服原文。国服数据库已确定存在；国服进度落后日服约一年，日服近一年新剧情的译文必然缺失，此时留空显示（FR-5）。

## 5 约束与风险
| 约束/风险 | 说明与对策 |
|---|---|
| 版权 | 仅限个人学习用途；遵守开源库许可（NFR-5） |
| 国服译文覆盖不全 | 国服数据库已确定存在，但国服进度落后日服约一年，新剧情无译文属常态；留空显示兜底（FR-5） |
| 强容错误命中 | 默认关闭，仅作为可选设置（FR-12） |

### 6.2 需求确认与决策记录

**初始确认（v1.0）**
1. 匹配容错 → 做成个性化设置（默认关闭容错）
2. 读音归一化 → 支持（输入假名可命中汉字写法台词）
3. 数据更新 → 随软件打包 + 手动替换数据文件，另额外开发一键从 GitHub 拉取最新数据库的功能（用户手动触发）
4. 增强功能 → 纳入：复制与收藏、Anki 导出、假名注音显示；不纳入：中文反查

**用户复核修正（v1.1）**
1. 形容词名词化派生（如 高さ）纳入检索范围（默认行为，不受容错级别影响）
2. 相近的不同词条（聞こえる 等）：弱、中容错级别下不匹配；仅在强容错级别下与 聞く 互通
3. Anki 导出移至后续扩展，第一阶段暂不开发；其优先级高于中文反查
4. 国服译文数据库已确定存在；国服进度落后日服约一年，部分日服剧情必然暂无国服译文，留空显示
