## 1. 项目概述

### 1.1 原始构想

利用游戏《世界计划》（Project Sekai，PJSK，日服）的剧情文本，制作辅助日语学习的软件：用户输入某个日语词汇、语法等表达，软件查询剧情中使用到该表达的对话，作为学习该表达的例句。

### 1.2 目标与价值

- 用户在学习日语（近似 JLPT 备考，但不限于备考）过程中，背到某个单词/语法时，希望找到 PJSK 剧情中的真实用例作为例句；
- 用自己喜欢的游戏剧情学日语，产生亲切感，提高学习兴趣、增强记忆。

### 1.3 目标用户

- 主要用户：软件作者本人（日语学习者 N3~N2、PJSK 玩家）；
- 潜在用户：社区中的其他 PJSK 爱好者/日语学习者（计划开源至 GitHub 等社区）。软件界面为中文。

### 1.4 参与者

| 参与者 | 说明 |
|---|---|
| 学习者 | 主要参与者：使用软件查询、学习例句 |
| 数据维护者 | 次要参与者：剧情数据的导入与更新（可与学习者为同一人） |
| 剧情数据库仓库 | 外部系统：GitHub/Gitee 上的开源剧情数据库，仅在数据更新时访问（非运行时依赖） |

## 2. 范围与边界

### 2.1 收录范围

- 剧情类型：主线剧情 / 活动剧情 / 卡面剧情（前篇·后篇）/ 区域对话 / 虚拟演唱会台词 / 生日·纪念剧情；
- 数据来源：GitHub/Gitee 上已取得作者同意的开源剧情数据库（候选如 SekaiViewer 系列仓库）；
- 兜底原则：库有什么就收录什么，收录范围随数据库实际内容而定。

### 2.2 明确不在范围内（v1）

- 歌词（无合适的开源数据库）；
- 中文反查（以中文搜日语例句）；
- 账号系统与云端同步、移动端；
- 配音、剧情图片；
- 收藏分类/备注；
- Anki 卡片导出列为后续扩展（优先级高于中文反查）；相近查询推荐列为后续版本。

### 2.3 平台

Windows 10/11 64 位桌面应用；免安装解压即用（或标准安装包）。

## 3. 功能性需求

| 编号 | 名称 | 优先级 | 描述 |
|---|---|---|---|
| FR-1 | 单词/短语查询（模糊查询） | 核心 | 用户输入日文单词、短语或短句，软件在本地剧情库中检索。匹配 = 子串（包含式）匹配 + 活用形扩展（FR-2）+ 双向读音归一化/表記ゆれ（FR-3）+ 按容错级别执行额外容错（FR-13）。输入约束：非空、不全为通配符、长度 ≤ 100 字符。口语、省略形（如「じゃね？」「ってば」「してる」）凡剧情文本中出现均可查到；不要求独立成词（查「高い」命中「高くない」，查「雨」命中「梅雨」）。 |
| FR-2 | 活用形扩展匹配 | 核心 | 动词、形容词、形容动词等有形态变化的词：输入基本形或其他任意形式，其全部活用形均纳入检索范围，包括：ます形 / て形 / た形 / ない形 / ば形 / 命令形 / 意向形 / 可能形 / 受身形 / 使役形 / 使役受身形 / 敬语，及复合表达（如「聞かせていただき」）；同时纳入口语缩约形（聞いてる、聞いとく、聞かなくちゃ、聞いたん 等）。边界规则：名词化派生（如 高い→高さ）默认纳入检索；相近的不同词条（聞こえる 等）默认不互通，仅在强容错级别下与 聞く 互通（见 FR-13）。 |
| FR-3 | 读音归一化与表記ゆれ | 核心 | 双向匹配，默认开启：① 输入含汉字 → 命中含该汉字的词及同读音的纯假名写法（查「食べる」命中「たべる」）；② 输入纯假名 → 命中假名书写形式及同读音的汉字写法；其中同音异义词（该读音对应多个不同词条，如 聞く/効く/利く）的汉字写法全量扩展仅在中/强容错级别生效，弱容错下仅命中书写一致的假名形式。查询与语料两侧统一做平假名/片假名互转、全角/半角统一、长音符（ー）容忍（始终生效）。读音归一化命中的相关度低于书写形式命中（见 FR-7）。 |
| FR-4 | 语法模式查询（通配符） | 核心 | 支持带通配符的模式查询，如「〜を〜にして」「〜てしまう」；通配符符号可在设置中指定（默认「〜」，可选 ……、＊、※ 等）。每处通配符在单句台词内匹配任意长度（含 0 字）的内容；模式中的固定部分同样适用 FR-2、FR-3。搜索界面应提供占位说明或示例提示。 |
| FR-5 | 结果展示 | 核心 | 每条结果显示：台词原文（命中部分高亮，注音见 FR-11）、说话角色、出处（剧情类型 + 剧情/活动名称 + 话数/章节 + 台词序号）、国服译文（有对应译文时显示，无则显示「暂无翻译」）。支持展开查看该台词前后几句对话。结果分页展示（每页条数可配置，默认 50）。不包含配音与剧情图片。 |
| FR-6 | 结果筛选 | 核心 | 筛选维度：剧情类型（主线 / 活动 / 卡面前篇·后篇 / 区域对话 / 虚拟演唱会台词 / 生日·纪念）、团体（Leo/need、MORE MORE JUMP!、Vivid BAD SQUAD、Wonderlands×Showtime、25時、ナイトコードで。、Virtual Singer）、角色、时间（日历选择日期范围 或 按活动列表选择，两种方式）。各维度可组合；筛选可在搜索前预设，也可对已有结果即时生效。 |
| FR-7 | 结果排序 | 核心 | 排序方式：相关度（默认）、剧情实装时间（活动/章节发布顺序），各支持升/降序。相关度打分规则：① 命中形式——书写形式完全命中 > 活用变形/派生命中 > 读音归一化命中 > 通配分隔命中；② 查询表达式（固定部分）覆盖率；③ 同句命中次数；④ 同分时按实装时间排序。 |
| FR-8 | 分页与结果量控制 | 核心 | 结果分页展示，每页条数可由用户指定，默认 50 条；结果总数超过 1000 条时提示「结果过多，建议筛选」，用户仍可翻页浏览（分页加载保证性能）。 |
| FR-9 | 复制例句 | 增强 | 一键复制选中例句（台词原文 + 说话角色 + 出处），是否附带译文/注音按个性化设置（FR-13）决定；界面提示复制成功。 |
| FR-10 | 收藏 | 增强 | 可将一条命中的例句（连同出处与上下文信息）加入本地收藏；支持取消收藏/移除；重复收藏不产生重复条目；提供收藏列表查看；v1 不做分类/备注。收藏数据本地持久化（存于用户数据目录，重装软件不丢失）。 |
| FR-11 | 假名注音显示 | 增强 | 台词上方标注假名读音；注音优先使用数据源自带注音数据，数据源不含注音时可用形态素解析生成读音（实现阶段按数据源情况二选一）；显示开关在个性化设置中（FR-13）。 |
| FR-12 | 剧情数据更新 | 核心 | 三种途径：① 随软件版本内置发布时最新的剧情数据；② 软件内「一键更新」按钮——用户手动触发，联网从指定 GitHub/Gitee 开源仓库拉取最新数据，校验格式与完整性后重建索引；③ 用户手动将符合格式的数据文件放入软件数据目录，软件检测后提示重建索引。更新失败（网络错误、仓库不可达）时给出失败提示并保留原有本地数据与索引。除数据更新外，全部功能离线可用。 |
| FR-13 | 个性化设置 | 核心 | 匹配容错级别：弱（默认）/ 中 / 强。弱 = 子串 + 活用形 + 双向读音归一化（同音词不做全量扩展）+ 通配；中 = 在弱基础上额外容忍促音、长音符、拗音等轻微书写差异，并启用同音异义词全量命中；强 = 在中基础上额外启用相近词条互通（聞こえる↔聞く 等）与编辑距离近似匹配（容忍少量假名拼写差异，注意可能引入不相关结果）。另含：默认排序规则、注音显示开关、通配符默认符号、复制内容选项、每页条数。设置持久化保存并即时生效。 |
| FR-14 | 启动与数据校验 | 核心 | 软件启动时校验剧情数据与索引的完整性；数据缺失或损坏时提示并引导通过 FR-12 更新；首次启动加载数据时显示进度。 |
| FR-15 | 无结果处理 | 核心 | 查询无命中时提示「未找到」，并显示查询建议（改用基本形、放宽通配符、调整容错级别）；v1 不做相近查询推荐。 |

## 4. 非功能性需求

| 编号 | 类别 | 需求 |
|---|---|---|
| NFR-1 | 平台与部署 | Windows 10/11 64 位；免安装、解压即用（或标准安装包）；支持安装/解压路径含中文与空格 |
| NFR-2 | 编码与输入法 | 界面及数据全程 Unicode（UTF-8）编码，正确显示中文与日文；所有输入框支持 Windows 中文输入法与日文输入法（微软拼音、微软日语 IME 等）正常输入与候选显示 |
| NFR-3 | 性能 | 数据规模数十万～百万台词行、本地索引；单次查询响应 ≤ 1s；冷启动 ≤ 10s；内存占用 ≤ 1GB |
| NFR-4 | 离线 | 除数据更新外，全部功能可离线使用 |
| NFR-5 | 易用性 | 主界面以搜索框为中心，筛选/排序位于搜索框下方，交互简单直观 |
| NFR-6 | 异常与容错 | 空输入、纯通配符、超长输入给出明确提示；无结果时显示空态与查询建议；数据文件缺失/损坏时启动提示并引导更新；首次启动加载数据时显示进度；更新失败保留旧数据 |
| NFR-7 | 数据安全 | 收藏与设置本地持久化（存于本地文件而非内存），重装软件不丢失 |
| NFR-8 | 合规 | 剧情文本版权归 SEGA / Colorful Palette 等权利方所有，本软件仅限个人学习用途，不商用、不分发剧情全文；所依赖的开源数据仓库须遵守其许可证，并在软件中注明数据来源 |
| NFR-9 | 可维护性 | 查询、索引、数据层解耦；数据更新与索引重建不依赖代码变更；结构模块化，为后续 Anki 导出、相近查询推荐、中文反查等扩展预留空间 |

## 5. 边界与异常场景

| 场景 | 处理 |
|---|---|
| 未下载数据/数据损坏时搜索 | 启动校验提示并引导更新（FR-14）；搜索时提示「请先更新剧情数据」 |
| 空输入 / 纯通配符 / 超 100 字符 | 明确提示输入无效 |
| 查询无命中 | 提示「未找到」+ 查询建议（FR-15） |
| 结果总数 > 1000 | 提示「结果过多，建议筛选」，仍可翻页浏览 |
| 更新下载失败 | 提示失败原因，保留原有本地数据与索引，可重试 |
| 高频虚词查询（如「ない」） | 依靠分页、筛选、超量提示缓解；属已知可接受行为 |
| 弱容错下纯假名输入遇同音异义词 | 仅命中书写一致的假名形式（既定规则，FR-3）；开中/强容错可全量命中 |
| 数据库缺少某类剧情 | 收录范围随数据库实际内容而定（兜底原则） |
| 国服译文缺失 | 显示「暂无翻译」（国服进度落后日服约一年，新剧情译文缺失属常态） |

## 6. 约束与假设

1. 剧情文本来源于第三方开源数据库（已获作者同意），软件非商用，版权风险较低；
2. 中文翻译仅采用国服官方译文，不使用社区翻译（授权问题）；国服数据库已确定存在，进度落后日服约一年；
3. 数据库更新由用户手动触发，软件不自动检查更新；
4. 无用户账号体系，无服务端，数据全部本地；
5. 强容错默认关闭（弱容错为默认，避免引入不相关结果）。
