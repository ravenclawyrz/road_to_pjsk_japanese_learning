# 需求访谈笔记（策略A：访谈式）

访谈者：PJSK 玩家兼日语学习者（N3~N2，奏推）
受访者：软件构想者
日期：2026-10-20

## 原始构想
利用《世界计划》(PJSK) 剧情辅助学习日语的软件：输入某个日语词汇/语法表达，查询到剧情中使用该表达的对话，作为学习例句。

## 第 1 轮记录

- Q1 软件本质：利用 PJSK 剧情辅助学习；核心功能 = 输入单词/语法表达 → 查询剧情中是否有该表达。
- Q2 使用场景：日语学习（近似 JLPT 备考但不限于）时，背到某个单词/语法，想在剧情中找更多例句辅助学习。动机：对喜欢的剧情有亲切感 → 更有兴趣、记忆更牢固。
- Q3 用户范围：先自用；效果好的话上传 GitHub 等社区，供其他 PJSK 爱好者使用。大作业与个人项目二合一。
- Q4 角色口癖查询（如 わんだほーい）原未设想，但原理与单词/语法查询类似，可自然覆盖；其他查法未定。

## 第 2 轮记录

- Q5 数据源：收录全部剧情类型（主线、活动、卡面支线、区域对话、虚拟演唱会台词）。文本来自 GitHub 开源数据库（已获作者同意）。计划做筛选功能（如按箱活筛选）。歌词：想收录但无合适的开源数据库，放弃。
- Q6 形态匹配：所有变形都应命中（"聪明"到全变形识别）。高频虚词（如"ない"）结果过多 → 考虑结果过多时只显示一部分。意识到会有人做各种"奇葩测试"。
- Q7 语法输入：最初设想直接敲，支持带分隔的模式如"……を……にして"。对"常用语法列表（按 JLPT 分级）供选择"的想法表示认可，可参考。
- Q8 输入：仅日语输入；暂不支持中文反查（国服翻译不准、中文表达丰富难对应；目的就是找日语例句）。
- Q9 结果内容：说话角色、出处、前后文（上下文）一定有；中文翻译可加；配音/图片不做。

## 第 3 轮记录

- Q10 筛选：按团体/角色/类型已考虑；按时间（只看某年之后）是访谈中新提出，用户认可并打算加入。全部计划实现。
- Q11 排序：自定义排序标准（类比游戏内歌单排序），如按相关度/时间；分页展示，一页最多约 50 条。
- Q12 查询外功能：收藏功能确定做；Anki 导出未定，可能后续完善；先做简单可用版（MVP）。
- Q13 口语表达：剧情文本里有的都能查到（口语、省略形均可）。
- Q14 平台：倾向 Windows 桌面端程序，略考虑 Web 应用；大概率桌面端。

## 第 4 轮记录

- Q15 表記ゆれ：未完全想好。初步设想：查带汉字的词 → 剧情中以纯假名书写（同读音）的也纳入；查纯假名 → 所有符合该读音的带汉字写法都纳入（即按读音归一化，双向）。
- Q16 查无结果：最初设想仅提示未找到；对"推荐相近查询"持开放态度，未定。
- Q17 数据更新：用户手动更新，软件内设按钮，点击后从 GitHub/Gitee 下载最新剧情仓库，查询基于该本地版本。
- Q18 收藏：存本地，不做账号系统。
- Q19 版权：剧情文本有现成 GitHub 开源库，非商用，问题不大，顾虑较小。
- Q20 典型使用流程（用户口述）：打开软件 → 搜索框（输入日文）→ 搜索框下有筛选与排序功能（搜索后也能筛选）→ 查看剧情文本+出处 → 可收藏 → 结束。核心界面元素：搜索框、筛选、排序、结果（文本+出处）、收藏。

## 第 5 轮记录（确认与验证）

- 需求复述（软件画像）获用户确认无误。
- C1 表記ゆれ最终规则：输入含汉字 → 匹配含该汉字的词 + 同读音假名写法；输入纯假名 → 匹配所有同读音的汉字写法（同音异义词全部命中，可接受）。
- C2 模式查询 v1 就做；通配符符号未定（访谈者建议"〜"，待用户拍板）。
- C3 中文翻译：国服官方译文有的就显示，没有的显示"暂无翻译"；不用社区翻译（授权问题）。
- C4 v1 仅提示"未找到"，相近查询推荐不做（以后再说）。
- C5 已找到的开源库含全部剧情类型；兜底原则=库有什么就收录什么。
- C6 默认排序=相关度（定义未定）；每页条数可指定，默认 50；结果总数超 1000 时提醒"结果过多，建议筛选"。
- C7 首次使用需联网下载剧情数据，之后离线可查询；未下载时搜索提示先更新数据。
- C8 收藏粒度=单条命中例句；v1 只做收藏列表，不做分类/备注。

## 第 6 轮记录（收尾）

- Q21 通配符符号：「〜」确认（访谈者建议，用户采纳）。
- Q22 匹配粒度：包含式匹配——"高い"命中"高くない"，"雨"命中"梅雨"（不要求独立成词）。
- Q23 时间筛选：同时提供日历（日期范围）和活动列表两种方式。
- 相关度定义记为待定项（留设计阶段）。

## 访谈结论摘要

- 原始构想核心功能（输入表达 → 查剧情例句）保持不变，访谈新增/明确：表記ゆれ规则、包含式匹配、模式查询（〜通配符）、筛选（团体/角色/类型/时间）、排序（默认相关度）、分页（默认50/页、1000+提醒）、收藏（本地列表）、数据更新机制（按钮+本地离线）、翻译策略（国服有则显示）、未找到提示。
- 明确不做（v1）：账号系统、Anki 导出、相近查询推荐、配音/图片、中文反查、歌词、收藏分类/备注。
- 待定：相关度定义、Web 版可能性。
