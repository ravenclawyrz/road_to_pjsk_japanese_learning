# 修订后的初步软件需求

> 项目：PJSK 剧情日语学习辅助软件（暂名：PJSK 例句检索）
> 获取方式：访谈式需求获取（6 轮访谈，访谈对象为软件构想者本人）
> 日期：2026-10-20
> 完整访谈记录见 [interview_notes.md](interview_notes.md)

## 1. 项目概述

### 1.1 原始构想

制作一个利用《世界计划》（Project Sekai，PJSK）剧情辅助学习日语的软件：输入某个日语词汇或语法表达，查询剧情中使用该表达的对话，作为学习掌握该表达的例句。

### 1.2 修订说明（访谈启发成果）

访谈在保留原始核心构想的基础上，澄清并新增了以下内容：

| 类别 | 内容 |
|---|---|
| 澄清 | 表記ゆれ匹配规则、包含式匹配粒度、无结果提示、数据更新机制、翻译策略 |
| 新增 | 语法模式查询（〜通配符）、多维筛选、自定义排序、分页、收藏、结果过多提醒 |
| 明确不做（v1） | 账号系统、Anki 导出、相近查询推荐、配音/图片、中文反查、歌词、收藏分类 |
| 待定 | 相关度排序的定义、Web 版可能性 |

### 1.3 目标与价值

- 用户在学习日语（近似 JLPT 备考，但不限于备考）过程中，背到某个单词/语法时，希望找到 PJSK 剧情中的真实用例作为例句；
- 用自己喜欢的游戏剧情学日语，产生亲切感，提高学习兴趣、增强记忆。

### 1.4 目标用户

- 主要用户：软件作者本人（日语学习者、PJSK 玩家）；
- 潜在用户：社区中的其他 PJSK 爱好者/日语学习者（计划开源至 GitHub 等社区）。

## 2. 范围

### 2.1 收录范围

- 剧情类型：主线剧情、活动剧情、卡面支线（前篇/后篇）、区域对话、虚拟演唱会台词（取决于开源数据库实际内容，库有什么收录什么）；
- 数据来源：GitHub 上已取得作者同意的开源剧情数据库（含上述全部类型）。

### 2.2 明确不在范围内（v1）

- 歌词（无合适的开源数据库）；
- 中文反查（以中文搜日语例句）；
- 配音、剧情图片；
- 账号系统（收藏仅存本地）；
- Anki 卡片导出、相近查询推荐、收藏分类/备注（后续版本考虑）。

## 3. 功能性需求

### FR-1 剧情数据管理（更新与离线）

- 软件内提供"更新剧情数据"按钮，点击后从 GitHub/Gitee 下载最新剧情仓库到本地；
- 查询功能基于本地数据，更新后无需联网即可查询；
- 更新失败（网络错误、仓库不可达）时给出失败提示，并保留原有本地数据。

### FR-2 单词/短语查询

- 用户在搜索框输入日文单词/短语，提交后返回命中的剧情对话；
- 匹配规则：
  - **变形识别**：所有活用变形均视为命中（如查"食べる"命中"食べた""食べられない""食べちゃった"）；
  - **表記ゆれ**：输入含汉字 → 匹配含该汉字的词及同读音的假名写法（查"食べる"命中"たべる"）；输入纯假名 → 匹配所有同读音的汉字写法（同音异义词全部命中，可接受）；
  - **包含式匹配**：不要求独立成词（查"高い"命中"高くない"，查"雨"命中"梅雨"）；
- 口语、省略形（如"じゃね？""ってば""してる"）凡剧情文本中出现均可查到。

### FR-3 语法模式查询

- 支持带通配符「〜」的模式查询，如「〜を〜にして」「〜てしまう」；
- 通配符「〜」表示任意内容；
- 搜索界面应对该语法有提示（如占位说明或示例）。

### FR-4 结果筛选

- 筛选维度：团体、角色、剧情类型（主线/活动/卡面支线/区域对话/虚拟演唱会）、时间；
- 时间筛选提供两种方式：日历选择日期范围、按活动列表选择；
- 筛选可在搜索前设置，也可在搜索出结果后进行。

### FR-5 结果排序

- 支持自定义排序标准（类比游戏内歌单排序），可选：相关度、时间等；
- 默认排序：相关度（具体定义见第 7 节待定项）。

### FR-6 分页与结果量控制

- 结果分页展示，每页条数可由用户指定，默认 50 条；
- 结果总数超过 1000 条时，提示"结果过多，建议筛选"。

### FR-7 结果展示

- 每条结果显示：剧情对话文本、说话角色、出处（所属剧情/活动、章节）、前后文（上下文）；
- 中文翻译：国服官方译文已有的显示译文；没有的显示"暂无翻译"；
- 不包含配音和剧情图片。

### FR-8 收藏

- 可将一条命中的例句加入收藏（含出处与上下文信息）；
- 收藏存于本地，无需账号；
- 提供收藏列表查看功能；v1 不做分类/备注。

### FR-9 无结果处理

- 查询无命中时提示"未找到"；v1 不做相近查询推荐。

## 4. 非功能性需求

| 编号 | 类别 | 需求 |
|---|---|---|
| NFR-1 | 平台 | Windows 桌面端程序（对 Web 应用有轻微倾向，大概率桌面端） |
| NFR-2 | 性能 | 常规查询响应流畅；结果超 1000 条时提示而非直接全部加载 |
| NFR-3 | 离线 | 除数据更新外，全部功能可离线使用 |
| NFR-4 | 易用性 | 主界面以搜索框为中心，筛选/排序位于搜索框下方，交互简单直观 |
| NFR-5 | 数据安全 | 收藏数据本地持久化，重装软件不丢失（存于本地文件，而非内存） |
| NFR-6 | 可维护性 | 结构模块化，为后续 Anki 导出、相近推荐等扩展预留空间 |

## 5. 边界与异常场景

| 场景 | 处理 |
|---|---|
| 未下载数据时搜索 | 提示"请先更新剧情数据" |
| 查询无命中 | 提示"未找到" |
| 结果总数 > 1000 | 提示"结果过多，建议筛选" |
| 更新下载失败 | 提示失败原因，保留原本地数据 |
| 高频虚词查询（如"ない"） | 依靠分页、筛选、超量提示缓解；属已知可接受行为 |
| 数据库缺少某类剧情 | 收录范围随数据库实际内容而定（兜底原则） |
| 同音异义词大量命中（输入纯假名时） | 属既定匹配规则的结果，用户已知晓并接受 |

## 6. 约束与假设

1. 剧情文本来源于第三方开源数据库（已获作者同意），软件非商用，版权风险较低；
2. 中文翻译仅采用国服官方译文，不使用社区翻译（授权问题）；
3. 数据库更新由用户手动触发，软件不自动检查更新；
4. 无用户账号体系，无服务端，数据全部本地。
